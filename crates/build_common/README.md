# `build_common` — 内核构建脚本公共逻辑——编译汇编文件、设置链接器参数

> **所属层级**：R1 原语层（构建基础设施）
>
> **依赖方向**：依赖 `cc`（外部）；被根 crate `build.rs` 和测试 crate 的 `build.rs` 使用

## 架构设计

### 在系统中的位置

`build_common` 是一个 `std` crate（构建脚本在宿主机运行，非 `no_std`），为内核及测试二进制的 `build.rs` 提供统一的汇编编译和链接器配置逻辑。所有需要编译 `.S` 汇编文件或设置架构相关链接器脚本的 crate 都通过调用 `setup_kernel_build()` 完成，避免在多个 `build.rs` 中重复配置交叉编译器参数。

### 设计决策

| 决策 | 选择 | 理由 | ADR |
|------|------|------|-----|
| 统一入口函数 | `setup_kernel_build(arch_dir)` | 单一调用点完成汇编编译 + 链接器设置，降低 `build.rs` 复杂度 | — |
| 自动发现 `.S` 文件 | 遍历 `arch_dir` 目录 | 新增汇编文件无需手动注册，减少遗漏 | — |
| 使用 `cc` crate | 委托交叉编译器调用 | 成熟的构建工具 crate，处理编译器探测和参数拼接 | — |

### 参考

- [`cc` crate](https://docs.rs/cc/) — Rust 构建脚本中编译 C/汇编的标准方案
- Linux 内核 Makefile — 交叉编译器选择和架构标志参考

## 模块细节

### 公共 API

| 类型/函数 | 用途 |
|-----------|------|
| `setup_kernel_build(arch_dir: &Path)` | 自动发现 `.S` 文件、编译汇编、设置链接器脚本 |

### 内部设计

| 内部函数 | 用途 |
|----------|------|
| `compiler_for(arch)` | 根据目标架构返回交叉编译器名称 |
| `extra_flags_for(arch)` | 根据目标架构返回额外编译标志 |

支持的架构：

| 架构 | 编译器 | 额外标志 |
|------|--------|----------|
| riscv64 | `riscv64-linux-gnu-gcc` | `-march=rv64gc -mabi=lp64d` |
| aarch64 | `aarch64-linux-gnu-gcc` | — |

### Safety 说明

本 crate 无 unsafe 代码。

### 错误处理

- 不支持的架构：`unreachable!`（编译期已由 `cfg` 限定，运行时不应到达）
- 目录读取失败：panic（构建脚本中合理——编译环境异常应立即报错）
