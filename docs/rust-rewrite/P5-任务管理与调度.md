# Phase 5：任务管理与调度

> **依赖**：Phase 4 | **预计时间**：3 周 | **复杂度**：极高

## 目标

完整任务子系统 — TCB、状态机、调度器（CFS/FIFO/RR）、clone/exit/wait/sleep/signal、SMP 负载均衡。

> **分期实施**：P5 分为三个子阶段：
> - **P5a（已完成）**：核心调度 — TaskState FSM、FIFO 调度器、TCB（ArceOS 风格）、schedule()、kernel_thread_bootstrap、多核验证
> - **P5b（已完成）**：生命周期扩展 — clone/exit/wait、sleep、block/wakeup、signal、阻塞 KMutex、CFS/RR 调度器、syscall 注册
> - **P5c（已完成）**：SMP 扩展 — per-CPU 调度锁、跨核任务窃取、负载均衡

## Rust 生态利用

| 能力 | 来源 | 说明 |
|------|------|------|
| 有限状态机 | Rust `enum` + `match` | 编译期穷举检查，替代 C++ `etl::fsm`（~300 行 → ~20 行） |
| 调度器特定数据 | Rust `enum` (tagged union) | 替代 C++ 裸 `union SchedData`，编译期类型安全 |
| 资源 ID | Rust `enum` 变体 | 每种资源携带正确类型（`Pid`/`VirtAddr`/`IrqNumber`） |
| 信号掩码 | `bitflags` (已有依赖) | 类型安全 + 不可屏蔽信号保护 |
| 热路径集合 | `heapless` (已有依赖) | 固定容量 Vec/Deque 用于调度队列 |

| TCB 引用计数 | `alloc::sync::Arc` | `Arc<TCB>` 替代裸指针，消除 use-after-free（来自 rCore） |
| 哈希表 | `hashbrown` (新增依赖) | no_std HashMap，task_table O(1) 查找 |

**不自己实现**：位集合（用 `bitflags`）、固定容量容器（用 `heapless`）、引用计数（用 `Arc`）。
**必须自己实现**：调度器、任务管理器、状态机、阻塞 mutex、UserSlice（内核特有逻辑）。

### TCB 所有权：ArceOS 风格扁平设计

调研了 rCore-Tutorial（SpinLock\<Inner\>）、Redox（RwLock）、ArceOS（原子+UnsafeCell）和 Linux Rust 后，
选择 ArceOS 模式——原子状态 + UnsafeCell 上下文，消除不必要的锁开销：

| 方面 | rCore (SpinLock\<Inner\>) | 本项目 (Atomic + UnsafeCell) |
|------|--------------------------|------|
| 状态转换 | 获取锁 → 修改 → 释放 | `AtomicU8::compare_exchange`（无锁） |
| 上下文访问 | 获取锁 → 取裸指针 → 释放锁 → switch | `UnsafeCell::get()`（sched_lock 已保护） |
| 适用场景 | 单核 | SMP 就绪 |

```rust
pub struct TaskControlBlock {
    // 不可变字段（创建后不变）
    pid: Pid,
    name: &'static str,
    is_idle: bool,
    // 原子字段（无锁读写）
    state: AtomicTaskState,
    exit_code: AtomicI32,
    // 锁保护字段（仅在 SCHED_LOCK + IRQ off 时访问）
    context: UnsafeCell<CalleeSavedContextWrapper>,
    kstack: Option<KernelStack>,
}

pub type TaskRef = Arc<TaskControlBlock>;
```

**并发保证**：
- `state`/`exit_code`：原子操作，任何核心可安全读取
- `context`：仅在 `SCHED_LOCK`（`lock_raw`）持有期间通过 `ctx_mut_ptr()` 访问
- 生命周期：`Arc` 引用计数自动管理，调度器队列和 `current` 各持有一份

### 调度器锁移交协议（P5a 实现）

P5a 使用单一全局 `SCHED_LOCK: SpinLock<()>` 保护调度状态。
`lock_raw()`/`unlock_raw()` 跨越 `switch_to` 实现锁移交：

```rust
/// 全局调度状态
struct SchedState {
    scheduler: FifoScheduler,
    tasks: Vec<TaskRef>,
    current: [Option<TaskRef>; MAX_CORE_COUNT],
    idle: [Option<TaskRef>; MAX_CORE_COUNT],
    next_pid: Pid,
}

pub fn schedule() {
    unsafe { SCHED_LOCK.lock_raw() };      // 1. 获取锁（禁中断）

    // 2. 将当前任务放回队列（Running → Ready）
    // 3. pick_next（或 idle 兜底）
    // 4. 若 same task → unlock_raw, return
    // 5. 获取 context 裸指针，drop Arc 引用

    unsafe { switch_to(prev_ctx, next_ctx) }; // 6. 上下文切换

    unsafe { SCHED_LOCK.unlock_raw() };    // 7. 恢复的任务释放锁
}

/// 新任务首次入口
pub extern "C" fn kernel_thread_bootstrap(entry: usize, arg: usize) -> ! {
    unsafe { task::release_sched_lock() }; // 释放继承的 sched_lock
    let entry_fn: fn(usize) = unsafe { core::mem::transmute(entry) };
    entry_fn(arg);
    task::exit(0);
}
```

> **P5b 扩展**：将全局 `SCHED_LOCK` 拆分为 per-CPU 调度锁 + 全局任务表锁，
> 支持跨核负载均衡时按核 ID 顺序获取锁。
