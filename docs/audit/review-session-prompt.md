# SimpleKernel 专项审计 prompt

仅在发起专项深度审计时使用；普通局部审查不需要完整阶段流程。
[Roadmap](review-roadmap.md) 维护范围、排查 checklist、协作与停止规则，
[进度](audit-progress.md) 维护当前状态与下一步。历史摘要只作证据，不作为新的执行授权。

## 可复制请求

```text
请对 SimpleKernel 的 {{目标目录或模块}} 执行专项审计。
核对 Git 基线与适用 AGENTS，读取 docs/audit/review-roadmap.md、
docs/audit/audit-progress.md 和目标源文件；按 Roadmap 流程输出审查报告。
范围限制：{{只读、排除项或其他约束}}。
本轮只交付报告，不直接实施，也不替作者接受 ADR。
```

## 报告格式

| 部分 | 要求 |
|------|------|
| 模块概述 | 职责、依赖、审查范围与 Git 基线 |
| 问题清单 | 严重度、精确位置、可达触发、影响、证据、测试缺口和最小修复方向 |
| 依赖与版本 | 当前版本、已核验的上游信息及来源；未核验时明确标记 |
| Crate 替代评估 | 候选及客观优缺点，标记待决，不自行替换 |
| 参考内核对比 | 来源、差异与 SAS/教学目标下的适用边界 |
| 设计讨论点 | 合理备选方案（含保持现状）、客观优缺点，ADR 待决，不代选 |
| 代码修改建议 | 优先级、需先补的回归和验证范围 |
| 文档产出与交接 | 实际缺失的设计/规则、已审范围、未决项、下一步及证据 |

严重度：高为正确性/安全问题，中为设计或维护问题，低为非功能性风格/文档问题。
没有证据的项写明未知，不用虚构的版本号、API 或历史测试结果填满表格。
报告完成后按 Roadmap 停止；后续实施以作者反馈和授权为准。
