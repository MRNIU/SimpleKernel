# Phase 6：设备框架与驱动

> **依赖**：Phase 4（核心）+ Phase 5（仅 VirtIO 阻塞 I/O）| **预计时间**：1.5 周 | **复杂度**：中低

## 目标

设备管理器、驱动注册、VirtIO 子系统、UART 驱动。**本阶段大幅利用 Rust 生态 crate，避免重复实现 VirtIO 协议栈和 ACPI 解析。**

## 2026-06-03 设备框架回看

> 本节是 P6 完成后的架构回看。历史 P6 计划仍记录当时实现路径；当前演进方向以
> [ADR-020](../adr/020-borrow-rdrive-patterns-local-device-framework.md) 和
> [设备子系统当前设计](device-subsystem-current.md) 为准。

`rdrive` 提供了值得参考的动态驱动框架：驱动注册描述符、probe level、priority、
FDT compatible 匹配、PCI probe 和 `rdif-*` 接口分层。但 SimpleKernel 不直接把
`rdrive` 作为核心设备框架引入。

原因：

- 设备框架是内核核心边界，会影响驱动所有权、MMIO、DMA、中断上下文和文件系统访问路径。
- `rdrive` 的设备句柄、`spin::Mutex` / `RwLock`、`mmio-api` 全局入口和 PCIe unsafe 边界
  与 SimpleKernel 当前的 `SpinLockIrq`、`memory::MmioRegion`、`crates/dma` 和 fail-fast
  规则不完全一致。
- 当前 `src/device/` 仍应作为本地门面，避免 `rdrive::Device<T>`、`rdif-*` 或 `mmio-api`
  直接扩散到 `fs`、`syscall`、`task` 等上层模块。

后续演进方向：

| 能力 | 方向 |
|------|------|
| 驱动注册 | 借鉴 `rdrive::DriverRegister`，实现本地 `DriverDescriptor` |
| Probe 分类 | 本地支持 Static / FDT，PCIe 后续按需求加入 |
| Probe 顺序 | 本地支持 `ProbeLevel` 和 `ProbePriority` |
| FDT 匹配 | 从集中式 `platform_bus` match 演进为 descriptor 驱动的 compatible 匹配 |
| 设备接口 | 新增本地 `BlockDevice` / `NetDevice` / `SerialDevice` 等能力 trait |
| 块设备门面 | `fatfs_adapter` 迁移到本地 `BlockDevice` 门面，减少对 VirtIO 具体类型的依赖 |
| 第三方兼容 | 如需复用 tgoskits 驱动，再单独评估 `rdif-*` 适配层 |

迁移约束：

- 第一阶段保留 `device_count()` 和 `virtio_blk()` 兼容入口，避免一次性破坏系统测试。
- MMIO 继续走 `memory::MmioRegion`，DMA 继续走 `crates/dma`。
- 自动链接段注册不是第一阶段目标；若后续采用，需同步修改链接脚本并新增链接段测试。

## Rust 生态利用

| 能力 | 来源 | 说明 |
|------|------|------|
| **VirtIO 完整协议栈** | **`virtio-drivers` 0.13.0** | blk/console/gpu/input/net 驱动全部由 crate 提供，只需实现 `Hal` trait |
| **ACPI 表解析** | **`acpi` 6.1.1** | RSDP/XSDT/MADT/FADT 全部由 crate 解析，只需实现 `AcpiHandler` trait |
| MMIO 访问 | `volatile` (P4 已引入) | 设备寄存器访问 |
| FDT 枚举 | `fdt` (已有依赖) | 设备树遍历 |

**不自己实现**：VirtIO 传输层、virtqueue、VirtIO 设备协议、ACPI 表结构。
**自己实现**：设备管理器框架、PlatformBus、UART 驱动（太简单不值得引入 crate）。

> **对比原计划**：原 P6 需要实现 VirtIO MMIO transport + split virtqueue + blk/console/gpu/input/net 共 ~1500 行代码。使用 `virtio-drivers` 后，仅需实现 ~50 行 `Hal` trait。

## 设计

### virtio-drivers Hal trait（核心 — 连接内核内存管理与 VirtIO crate）

`virtio-drivers` 通过一个 `Hal` trait 与内核交互。我们只需实现这个 trait：

```rust
use virtio_drivers::{Hal, BufferDirection, PhysAddr as VirtioPhysAddr};

pub struct SimpleKernelHal;

unsafe impl Hal for SimpleKernelHal {
    /// 分配 DMA 缓冲区 —— 调用 P3 的帧分配器
    fn dma_alloc(pages: usize, _direction: BufferDirection)
        -> (VirtioPhysAddr, core::ptr::NonNull<u8>)
    {
        let paddr = memory::alloc_frames(pages).expect("DMA alloc failed");
        let vaddr = memory::phys_to_virt(paddr);
        (paddr.as_usize(), NonNull::new(vaddr.as_mut_ptr()).unwrap())
    }

    /// 释放 DMA 缓冲区
    unsafe fn dma_dealloc(paddr: VirtioPhysAddr, _vaddr: core::ptr::NonNull<u8>, pages: usize) {
        memory::free_frames(PhysAddr::new(paddr), pages);
    }

    /// 物理地址 → 虚拟地址（内核使用直接映射）
    unsafe fn mmio_phys_to_virt(paddr: VirtioPhysAddr, _size: usize)
        -> core::ptr::NonNull<u8>
    {
        let vaddr = memory::phys_to_virt(PhysAddr::new(paddr));
        NonNull::new(vaddr.as_mut_ptr()).unwrap()
    }

    /// DMA 缓冲区共享（直接映射下 phys == virt）
    unsafe fn share(buffer: core::ptr::NonNull<[u8]>, _direction: BufferDirection)
        -> VirtioPhysAddr
    {
        memory::virt_to_phys(VirtAddr::new(buffer.as_ptr() as *const u8 as usize)).as_usize()
    }

    unsafe fn unshare(_paddr: VirtioPhysAddr, _buffer: core::ptr::NonNull<[u8]>,
                      _direction: BufferDirection) {
        // 直接映射下无需额外操作
    }
}
```

### 使用 VirtIO 块设备

```rust
use virtio_drivers::device::blk::VirtIOBlk;
use virtio_drivers::transport::mmio::{MmioTransport, VirtIOHeader};

/// 从 FDT 探测 VirtIO MMIO 设备
fn probe_virtio_blk(mmio_base: PhysAddr, size: usize) -> KResult<VirtIOBlk<SimpleKernelHal, MmioTransport>> {
    let vaddr = memory::map_mmio(mmio_base, size)?;
    let header = NonNull::new(vaddr.as_usize() as *mut VirtIOHeader).unwrap();
    let transport = unsafe { MmioTransport::new(header) }
        .map_err(|_| ErrorCode::InvalidMagic)?;
    VirtIOBlk::new(transport)
        .map_err(|_| ErrorCode::DeviceError)
}
```

### PlatformBus（FDT 枚举）

```rust
/// 遍历 FDT，匹配 compatible 字符串并调用对应探测函数
pub fn platform_bus_probe(fdt: &KernelFdt) -> KResult<()> {
    for node in fdt.all_nodes() {
        if let Some(compatible) = node.compatible() {
            match compatible {
                c if c.contains("virtio,mmio") => {
                    let reg = node.reg().ok_or(ErrorCode::FdtPropertyNotFound)?;
                    probe_virtio_mmio(PhysAddr::new(reg.address), reg.size)?;
                }
                c if c.contains("ns16550a") => { /* 探测 UART */ }
                c if c.contains("arm,pl011") => { /* 探测 PL011 */ }
                _ => {} // 未知设备，跳过
            }
        }
    }
    Ok(())
}
```
